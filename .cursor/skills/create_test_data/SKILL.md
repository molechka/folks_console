# Наполнить базу тестовыми данными

Вызывай этот скилл по запросу «наполни БД».

Создать 30 карточек folks с разными ФИО и разной степенью наполненности. Девайсы у одного фолкс могут быть от 0 до 6 штук.

Сервер уже поднят с четырьмя демо-участниками из `data.sql`. Этот файл, `schema.sql` и тесты не меняй. Карточки добавляй пачкой `POST /create` в живую базу. Повторный запуск добавляет ещё 30, уже созданные не удаляй. После перезапуска процесса снова останутся только демо-строки — это ожидаемо.

Базовый адрес: `http://localhost:8088/rest/services/folks/v1`. Тело — `application/json`. Даты — `dd.MM.yyyy`.

## Перед отправкой

1. Проверь, что сервер отвечает: `POST /search` с телом `{"query":""}`.
2. Если порта 8088 нет, подними приложение командой из `AGENTS.md` и дождись ответа search. В выдаче должны быть демо-участники (Иванов, Иванова, Сидоров, Смирнова).
3. Запомни число карточек до пачки и собери уже занятые ФИО, чтобы новые тройки их не повторяли.

## Тридцать запросов

Каждый запрос — один `POST /create`. Id не передавай: его выдаёт сервер.

У каждой карточки своё ФИО. Тройка фамилия + имя + отчество не совпадает с другими в этой пачке и с уже загруженными. Одинаковая фамилия у разных людей допустима. Имена на русском, кириллицей.

Наполненность — три равные группы по 10. Незаполненное поле в `field` не клади.

| Группа | Что отправить |
| --- | --- |
| малая | только часть ФИО: у части карточек нет `name`, у части нет `patronymic`. Без компании, должности, города и остальных полей |
| средняя | `surname`, `name`, `patronymic`. Из `company`, `position`, `city` — одно или два поля, не все три |
| полная | ФИО, `preferredName`, `gender`, `birthDate`, `birthPlace`, `firstConfDate`, `company`, `position`, `jobStartDate`, `author`, `city`, `speaker`, `organizator`, `vipFlag`, `visitCount`, `averageRating`, `language`, `actualityDate` |

В полной группе часть карточек — докладчики (`speaker` = `true`), часть — оргкомитет (`organizator` = `true`).

Перечисления передавай именем, не числом. У пола в контракте написано `FAMALE`.

| Поле | Значения |
| --- | --- |
| `gender` | `UNKNOWN`, `MALE`, `FAMALE` |
| `vipFlag` | `UNKNOWN`, `FALSE`, `TRUE` |
| `speaker`, `organizator` | `true`, `false` |

В средней и полной группах встречаются все три значения `gender`. `averageRating` — строка с двумя знаками (`4.80`).

Длины, длиннее сервер не примет:

| Поле | Макс. |
| --- | --- |
| `name`, `patronymic`, `preferredName` | 100 |
| `birthPlace` | 50 |
| `author` | 20 |
| `city` | 20 |
| `language` | 10 |

## Устройства

Число устройств у одной карточки — от 0 до 6. В пачке из 30 каждый размер встречается хотя бы раз. Число не привязано к группе наполненности.

Ноль устройств — ключ `attribute` не передавай. Иначе каждое устройство — элемент `attribute` с `type` = `DEVICE` и своими `field`. Id устройства не передавай.

В списке UI устройство видно как «модель / ОС», поэтому заполняй `model` и `os`. `type` тоже заполняй. Колонка `type` — `varchar(10)`, значение `WINDOWSPHONE` не отправляй.

Допустимые `type`: `UNKNOWN`, `IPHONE`, `IPAD`, `SAMSUNG`, `LENOVO`, `NOKIA`, `BLACKBERRY`, `YOTAPHONE`, `OTHERS`.

Допустимые `os`: `UNKNOWN`, `IOS`, `ANDROID`, `WINDOWS`, `OTHERS`.

Модели и серийные номера внутри пачки не повторяй. `author` устройства — не длиннее 20 символов.

## Тело запроса

Малая карточка без устройств:

```json
{
  "folk": {
    "field": [
      { "name": "surname", "value": "Кузнецов" }
    ]
  }
}
```

Карточка с устройством:

```json
{
  "folk": {
    "field": [
      { "name": "surname", "value": "Орлова" },
      { "name": "name", "value": "Анна" },
      { "name": "patronymic", "value": "Игоревна" },
      { "name": "company", "value": "HFLabs" },
      { "name": "city", "value": "Казань" }
    ],
    "attribute": [
      {
        "type": "DEVICE",
        "field": [
          { "name": "type", "value": "IPHONE" },
          { "name": "os", "value": "IOS" },
          { "name": "model", "value": "iPhone 13" },
          { "name": "serialNumber", "value": "SN-1001" },
          { "name": "author", "value": "seed" }
        ]
      }
    ]
  }
}
```

Ответ create содержит выданный `id` и вложенные `DEVICE`. Если ответ не 200, останови пачку и покажи тело ошибки. Не досылать оставшиеся запросы, пока не ясно, почему этот не прошёл.

## Проверка

1. Успешно ушли ровно 30 запросов.
2. Повторный `POST /search` с `{"query":""}` возвращает на 30 карточек больше, чем до пачки.
3. Среди новых нет двух одинаковых троек ФИО. В малой группе нет компании, должности и города. В средней нет карточки, где заполнены все три. В полной есть поля из таблицы выше.
4. Число `attribute` с `type` = `DEVICE` у новых карточек лежит в 0…6, и каждое число от 0 до 6 есть хотя бы раз.
